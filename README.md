# Jarvis Mobile

Андроид-клиент к агентам Claude Code и Codex, которые работают **на других
машинах**: VPS, рабочей станции, домашнем сервере. Телефон показывает, кто
работает, кто упёрся в вопрос и кто закончил, даёт прочитать диалог и ответить.

Это спутник [Jarvis](https://github.com/Sergey-Chernyshev/jarvis), а не его
замена. Полная картина — история, статистика, голос, доска задач — остаётся на
ноутбуке. Здесь ровно то, ради чего достают телефон.

## Как это работает

```
телефон                                    машина с агентом
───────                                    ────────────────
Jarvis Mobile ──ssh -L 127.0.0.1:*:7717──▶ jarvis-node
   │  (sshj, ключ или пароль)                  ▲
   ├─ GET /events?since=<курсор>  ◀─ кольцевой буфер
   ├─ GET /file?path=&from=       ◀─ кусок транскрипта
   └─ POST /reply · /keys         ──▶ tmux -L jarvis
                                          ▲
                          claude / codex ─┘
```

Телефон говорит с узлом **напрямую**, а не через ноутбук: смысл приложения в
том, чтобы видеть агентов, когда ноутбук закрыт.

Узел наружу не слушает ничего. По умолчанию это unix-сокет с правами 0600, но
форвард на unix-сокет — расширение OpenSSH (`direct-streamlocal`), которого
SSH-библиотеки под Android не умеют. Поэтому на машине надо включить слушатель
на петле:

```bash
systemctl --user edit jarvis-node.service
# [Service]
# Environment="JARVIS_NODE_TCP=127.0.0.1:7717"
systemctl --user restart jarvis-node
```

Наружу это по-прежнему не открывает ничего: адрес обязан быть петлёй, иначе
узел откажется стартовать. Но к порту на петле может подключиться любой
пользователь **той** машины — на машине, где ты не один, лучше не включать.

## Чего здесь нет и не будет

Узел сознательно ничего не интерпретирует: он отдаёт сырые конверты хуков.
Поэтому статусы приложение считает само — и считает **грубее**, чем настольный
Jarvis: работает / спрашивает / закончила. Повторять настольный редьюсер один в
один здесь нельзя: получился бы второй источник правды, который неизбежно
разъедется с первым.

Отсюда границы:

* нет истории, статистики и расхода — они живут на ноутбуке;
* нет сводок ходов и заголовков сессий — их считает служебная модель на ноутбуке;
* ответ на сложный пикер (несколько вопросов, свой текст) — с ноутбука; здесь
  есть только выбор варианта цифрой;
* нет push-уведомлений: для них нужен сервер, а его в этой схеме нет и не
  задумано.

## Безопасность

* Единственный транспорт — твой обычный SSH. Ключ или пароль лежат в
  `EncryptedSharedPreferences`: ключ шифрования держит Keystore устройства.
* Отпечаток хоста запоминается при первом подключении и проверяется дальше.
  **Смена** известного отпечатка — отказ: именно она, а не первое знакомство,
  является признаком подмены.
* Приложение просит одно разрешение — интернет.

## Сборка

```bash
./gradlew assembleDebug     # app/build/outputs/apk/debug/
./gradlew testDebugUnitTest
```

Нужны JDK 17 и Android SDK (compileSdk 35). Отладочный APK на каждый коммит
собирает CI и кладёт артефактом.

## Статус

Ранняя версия. Проверено: сборка и юнит-тесты в CI, протокол узла — на живой
машине со стороны узла. На настоящем телефоне сквозной путь ещё не гонялся.
